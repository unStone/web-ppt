## Question

哪些版面问题可以不看图、用确定性计算发现，并给出 Agent 能直接定位和修正的结果？

## 检查项

| reason | 判定依据 | 复用 |
|---|---|---|
| `text-overflow` | 文字排版高度超出文本框，且没有生效的 autofit | `layoutText`、`resolveTextScale` |
| `element-overlap` | 同页非组合内元素的包围盒交叠超过阈值；背景与装饰元素按规则排除 | 001 的包围盒 |
| `off-canvas` | 元素包围盒越出页面 | 同上 |
| `low-contrast` | 文字颜色与其下方有效填充的对比度低于阈值 | 有效填充与主题色求值 |
| `missing-font` | 文字使用的字体既未嵌入也不在宿主提供的字体列表中 | `collectFonts`、字体 Provider |
| `placeholder-prompt-left` | 占位符仍显示版式的提示文字 | 占位符继承 |
| `image-distorted` | 图片显示宽高比与原图宽高比偏差超过阈值，且不是裁剪造成的 | `readImageMetadata`、裁剪信息 |

每项输出 reason、页号、元素 id（与 001 一致）、包围盒及触发阈值的实测值。

## 完成条件

- 每个检查项都有正例与反例固件，固件由 `tooling/make-*.mjs` 确定性生成。
- 在全部现有固件上运行，逐条复核报告；误报写入本票 Answer 并据此确定阈值，不预设数值。
- 测字在 Node 中走注入的测量函数（字体 Provider），在浏览器中走 Canvas；两种环境给出相同 reason 集合，差异逐条解释。
- 结果在独立进程中两次运行逐字节一致。

## 不做

- 不评价审美（配色、留白比例）；不自动修复，修复由 Agent 通过 004 的命令完成。

## Answer

`@web-ppt/edit-core/lint` 提供只读异步检查，复用 describe 的稳定身份和当前投影；输出类型生成的 Schema 同包发布。复杂颜色通过独立 `/lint/sampler` 接入宿主光栅化器；协议、取消与依赖失败见 [API](../../../api/agent-layout-lint.md)，实现决策见 [技术方案](../../../design/agent-layout-lint.md)。

| 原始分布与复核 | 采用的判定 |
|---|---|
| 未筛选的越界候选 23 项，最小 3.30127px；没有接近浮点舍入的微小偏差 | 容差 0.01px，仅吸收浮点误差 |
| 文本外框相交候选 46 对，中位数 0.1、75% 分位约 0.2727；小比例边框交叠与真正内容覆盖分开复核 | 相交面积占较小外框超过 0.25；普通组成员不互报，背景图片和无文字装饰排除 |
| 94 张图中 43 张比例偏差低于 0.01，中位数约 0.07386；裁剪先从原始尺寸扣除 | 对称比例偏差超过 0.05；旋转不算拉伸，裁剪后仍拉伸则报告 |
| 对比度采用 W3C AA；临界固件为 4.4961700436 | 普通字 4.5、大字 3；比较前不四舍五入 |

固件中的刻意重叠、拉伸和越界仍是观察结果，不根据文件名隐藏。字体检查比较声明字体需求与显式库存，可能包含未使用的脚本槽；这与逐字形覆盖不同。原始提示与当前正文完全一致可能是作者有意保留，报告保留匹配文字供调用者判断。

完全遮挡文字的回归曾实测失败；辅助图改为显式透明，并保留遮挡形状、图片的 alpha 后通过。半透明遮挡额外采样字形覆盖，避免将抗锯齿边缘当作颜色来源。

超宽字形的回归覆盖左、居中和右对齐；右对齐向左溢出曾实测漏报，改为同时检查列框的左右边缘后通过。

14pt 粗体按与渲染器一致的 pt→px 运算顺序判断，避免浮点尾差被归为普通字；真实浏览器验证对比度 3.5448862153 时采用大字阈值 3。

模板提示按 DrawingML 的文本 run、字段和换行读取，忽略 XML 标签之间的排版空白；确定性固件使用多 run 与换行缩进，验证提示检测不受 XML 格式化影响。

## Resolution

2026-10-22，Node v24.3.0 验收。

| 维度 | 证据 |
|---|---|
| 检查与边界 | 七项正反例、裁剪、普通组合去重、表格、三种文字对齐、14pt 粗体、透明与遮挡采样、模板多 run；缺依赖、取消、迟到回调、进度失败、调用时快照与只读均通过 |
| 测字与确定性 | 真实 HarfBuzz Provider 覆盖七项；全部 176 份固件的 Node 注入真实 Canvas 观测，与浏览器 reason 集合一致；两个新进程逐字节一致 |
| 报告复核 | 175 份完整报告共 2188 条观察，全部通过生成 Schema 与触发条件复核。`sample-editor-image-content.pptx` 的 `example.invalid` 外链无源图字节，唯一预期失败为 image-metadata-unavailable，不伪造尺寸或交付半份报告 |
| 发布边界 | npm 内容、无源码 paths 的外部 TS 调用、无 DOM 及输入图审计通过；发布浏览器 bundle 不含 packages/*/src；独立构建后 core/edit-core 默认闭包逐文件 SHA-256 一致 |
| 按需成本 | lint 20822B、sampler 13840B gzip；15 页、17 对象、已准备真实字宽/采样，5 进程中位数：冷加载 22.85ms、检查 7.83ms、堆增量 9373416B（含 peer 与解析）。sampler 单独冷加载 13.29ms、堆增量 1690472B（含 core，未调用宿主光栅化器） |
| 基准修复 | 无 dist 的实际建模、1000 帧恢复与三页保存通过；210 页完整预算通过：常驻增量 23.7%、恢复 386.2ms、50MB 三页保存 125.8ms，没有放宽预算 |
| 全仓 | check → test（含性能）→ build → verify 全部通过；176 份固件 / 597 页 / 1194 对 SVG 等价；最终固件两次生成 SHA-256 均为 3a86523b449f005df61b859c1f5b7fce2a87e25d970c76944b4f12ca8ff9a481 |

检查不产生编辑历史、恢复帧、协同操作或保存产物，沿用现有编辑和保存链路。Windows PowerPoint 真机按既有约定暂缓。
