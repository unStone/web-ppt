## Question

lint 观察是否真的提高 Agent 完成编辑任务的成功率？怎样用可复跑的方式证明？

## 范围

| 部分 | 说明 |
|---|---|
| 任务 | 基于固件的编辑任务，每个任务有机器判定条件（describe 字段比对、lint 零错误、保存可重开） |
| 对照 | 同一 Agent、同一任务，分别在提交结果附带 lint 与不附带 lint 两种配置下运行 |
| 记录 | 任务定义、判定脚本、会话记录、产物与结果落盘到仓库工具目录 |

## 完成条件

- 任务、判定与结果文件可在仓库内一条命令复跑判定。
- 本票 Answer 记录两种配置的完成率与失败原因分布，并说明样本量的局限。

## 不做

- 不作为发布门禁；评测依赖外部模型，结果只作为接口设计的证据。

## Answer

本次受控样本未显示自动 lint 的确定性成功率收益。采用 Codex CLI `0.166.0`，两组固定请求 `gpt-6.1-sol`、`ultra`，使用相同公开 Skill、工具 Schema、输入和提示；每次预算 240 秒、64 次 MCP 调用，条件顺序交替，每类仅一对。

| 指标 | 提交自动附带 lint | 不附带自动 lint |
|---|---:|---:|
| 计划 / 实际启动 | 8 / 8 | 8 / 8 |
| 预算内完整流程成功 | 5/8（62.5%） | 6/8（75%） |
| 实际保存文件语义通过 | 6/8（75%） | 7/8（87.5%） |
| 资源上限终止 | 2（调用上限 1、墙钟上限 1） | 2（调用上限 1、墙钟上限 1） |
| 外部服务失败 | 1（model at capacity） | 0 |

排除含容量故障、无法作有效比较的一对后，七个可评估配对的完整流程成功均为 5/7：四对都成功，一对仅有反馈成功，一对仅无反馈成功，一对都未完成。资源限制是统一预算下的终止观测，不等同于外部平台故障；原始诊断保留，逐原因计数可能重叠。

样本覆盖干净对照及七项布局检查，使用固定 Latin 字体和实色背景；字体缺失例只覆盖未注册 EA 备用声明。仅一轮八对、推荐 Skill 本身要求显式检查，且服务端实际 model 标签未由 CLI 公开，因此不外推普遍因果效应。

原始模型样本冻结于 `a8710e1`，后续 `16dfe77` 补全间接源码指纹、必填交付消息和资源分类后，仅重判同一批记录。173 个原始文件逐字节未变，逐条完整流程/语义通过状态也未变；当前报告明确 `sourceMatches=false`，不伪装成旧判定实现精确重现。

| 复核入口 | 内容 |
|---|---|
| `npm run eval:agent` | 一条命令离线重判默认真实数据，不调用模型 |
| [完整结果](../../../../tooling/agent-eval/records/codex-2026-11-04/results.json) | 计划、逐条判断、完整七项检查、失败分布与 usage |

## Resolution（2026-11-04）

| 验收项 | 结果 |
|---|---|
| 受控任务与生产 MCP 可达性 | 输入/参考固件确定性、真实字体、完整七项检查、原生语义保护及逐类实际修复通过 `npm run test:agent-eval` |
| 真实配对证据 | 全部八对独立 CLI 编辑试验及失败均保留；可移植文件字节数与哈希、原始/交付协议、成功保存哈希和来源已复核，Git 索引覆盖全部证据 |
| 一条命令重判 | `npm run eval:agent` 离线重判全部记录通过，完成率和失败分布与上述结果一致，不调用模型 |
| 工程门禁 | `npm run check`、`npm test`、`npm run build`、`npm run verify` 全部通过；发布包边界使用真实 npm 打包正反例验证 |

本票只提供受控样本证据，不据此调整生产接口行为。Windows PowerPoint 真机仍按用户要求暂缓，未计为通过。
