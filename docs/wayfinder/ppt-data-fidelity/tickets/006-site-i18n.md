## Question

官网首页、查看器和编辑页目前只有中文。如何提供完整中英文产品体验，同时保持发布包零文案、静态部署和按需
模板入口不变？

建立类型安全的站点词条目录与唯一语言解析规则，覆盖 HTML metadata、导航、上传/错误/恢复、工具栏、模板选择、
无障碍标签和动态状态；显式 URL 语言优先于已保存偏好，再回退浏览器语言。语言切换保留当前文件、编辑历史、
选区和页面位置，不重建编辑会话；未知语言稳定回退英文，缺词在构建时失败。静态中文/英文可被搜索引擎直接
发现，`hreflang`、canonical、JSON-LD 和 Open Graph 与页面语言一致。

验收覆盖两种语言的三张页面、键盘与触屏入口、模板延迟加载、错误与恢复分支、刷新记忆、深链接和无脚本元数据；
真实 Chrome 检查可见文本及可访问名称，构建守卫证明 core/edit-core/editor 不含站点词条。

## 阶段推进（保持 open）

| 基础增量 | 后续仍须完成 |
|---|---|
| 三张页面共用中文源文案与类型安全英文目录，构建输出同级 `*.en.html` 静态镜像 | 查看器和编辑器其余动态工具文案 |
| URL → 保存偏好 → 浏览器语言；未知语言回退英文，中文默认不加载英文目录 | 框架视图生成的无障碍名称与完整键盘/触屏语言矩阵 |
| 原地切换静态 UI、标题/文稿类型、撤销重做状态和元数据，不重建编辑会话；中文地址保留 | 全站双语验收，不能以静态页面翻译代替完成态 |

源文案作为词条身份；只认领页面骨架及显式消息绑定，不遍历或按词猜测翻译幻灯片、文件名、样本标题和署名。
参数以文本插值传递，静态构建对缺词失败；两个语言页面共享结构和脚本资源，避免维护两套会漂移的 HTML。
