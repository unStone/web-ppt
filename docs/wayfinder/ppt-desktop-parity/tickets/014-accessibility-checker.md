## Question

作者怎样在交付前一次看到文稿里的无障碍问题（缺替代文字、阅读顺序混乱、对比度不足、缺标题），并逐条定位修复？

## 现状

已有替代文字命令 `SetAltText`、选择窗格与画布阅读顺序语义，以及 `edit-core/lint` 的对比度检查；没有面向作者的汇总检查与修复入口。

## 范围

| 检查 | 复用 |
|---|---|
| 图片、图表、SmartArt、媒体缺替代文字 | `describe` 元素类型与 `SetAltText` |
| 文字对比度不足 | `lint` 的对比度观察 |
| 页面缺标题或标题重复 | 占位符角色 |
| 阅读顺序与视觉顺序不一致 | 元素层级与包围盒 |
| 表格缺标题行、合并单元格 | 表格模型 |
| 结果 | 每条带稳定 reason、页号与元素 id；产品层逐条定位并给出修复动作（产品待确认） |

## 完成条件

- 每项检查有正反例固件，确定输出；现有固件上的误报逐条复核。
- 修复动作经现有命令执行，可撤销。

## 参考

上游无此能力；检查项依据 WCAG 2.2 与 PowerPoint 辅助功能检查器的公开规则分类。
