## Question

2026-08-28 实测：`npm test` 与官网构建、另一个 Chromium 实例并行时，删除/撤销/重做 60 元素契约测得
p95 14.0/12.9/5.3ms 而判失败；同机安静环境立刻复测为 4.7/3.4/1.8ms 全绿。性能预算是接口契约不能放松，
但它现在把「机器忙」误报成「代码退化」。如何把功能正确性与性能预算隔离，让开发机上的偶发负载不产生假红灯？

| 方向 | 说明 |
|---|---|
| 分离断言 | 功能终态（DOM/选区/历史一致性）与性能 p95 分开报告：功能失败永远红；性能超标带环境自检结果 |
| 负载自检 | 测前/测中采样一个已知基线操作（如空转 rAF 间隔或固定计算耗时），超过阈值判定环境受扰 → 自动重测一轮，仍超标才红 |
| 不做的 | 不放宽任何预算数值；不引入「本地跳过性能」开关（CI 与本地必须同一契约） |

验收：复现脚本（人为并行 CPU 负载）下功能断言仍绿、性能断言给出「环境受扰重测」路径；安静环境行为与现状
逐字节一致；对 `tooling/test-editor-browser.mjs` 全部性能契约生效；全部门禁绿。
