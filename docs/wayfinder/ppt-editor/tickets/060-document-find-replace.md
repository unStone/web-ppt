## Question

如何让用户在查看和编辑模式中快速查找整份演示文稿的可见文字，并在编辑模式下安全地替换当前命中或全部命中，同时让 headless 命令、历史、画布、多视图、保存恢复及 React/Vue 宿主共享同一确定性结果？

`@web-ppt/edit-core` 必须公开无 DOM 的文字查找 seam，并以稳定页序、元素绘制序、表格行列序和 UTF-16 偏移返回匹配；覆盖普通形状、组内文字和表格单元格，能跨 run 命中但不把段落、公式对象或动态字段边界误拼成普通字符串。查找默认按 Unicode 字面量匹配，支持大小写敏感与整词选项，空查询和非法纯数据输入要明确拒绝；结果必须包含足够的稳定身份、范围和上下文，让宿主无需重扫模型即可显示计数、预览并前后导航。

`ReplaceText` 必须是严格纯 JSON 命令，支持当前命中和文档/指定页面范围内的全部命中；命令只对执行开始时的快照匹配一次，替换文本即使再次包含查询也不能循环。跨 run 替换要保持未命中内容、段落结构及未触碰格式，插入文字采用命中起点的有效字符格式；表格单元格、空替换、跨页批量替换、撤销/重做、恢复回放和连续保存必须精确。只读文档、不可编辑文本、锁定目标、失效的精确命中、非法范围或任一写回风险必须在落模前原子拒绝，不能静默做部分替换；一次“全部替换”只形成一个历史单元。

`@web-ppt/editor` 提供会话级查找控制器：查看模式可查找、导航和高亮，编辑模式额外允许替换当前/全部；`Ctrl/Cmd+F` 打开查找，`Ctrl/Cmd+H` 打开替换，`Enter`/`Shift+Enter` 前后导航，`Escape` 关闭。命中跨页时切换到稳定页身份并让事件视图显示当前命中；普通选区和文字编辑状态不能被后台重扫破坏。文档事务后只增量更新受影响页面的索引，并保持当前命中的稳定重基或给出明确“已失效”状态；多视图、adapter、React/Vue 只消费同一个控制器，不复制状态机。宿主通过公开状态、动作、ARIA 文案和数据属性渲染自己的搜索栏，核心包不内置产品 UI。

确定性固件覆盖跨页重复项、大小写与 Unicode、跨 run、段落边界、组、表格、字段/公式、锁定目标、未知相邻 XML 和没有命中的情况。Node 契约从公开 seam 验证顺序、选项、严格性、原子历史、恢复及最小 XML；真实 Chromium 验证快捷键、前后循环、跨页、多视图、查看/编辑权限、增量 DOM 与 adapter 生命周期。200 页索引建立和查询、60 元素页命中导航与替换反馈必须给出实测并守住现有交互预算；默认预览路径不得建立搜索索引。保存产物进入统一 Office 清单并由 LibreOffice 实际打开；Windows PowerPoint 真机继续服从任务“证明 M1 最小写回与真实软件兼容”的证据契约。

## Resolution

- `findText` 与严格纯 JSON `ReplaceText` 贯通无 DOM 查询、精确命中和页面范围批量替换：结果按稳定页序、绘制序与表格行列序返回 UTF-16 范围，可跨 run 但不跨段落、字段或公式；隐藏元素/祖先不进入可见文字。Unicode 整串大小写折叠覆盖希腊 final sigma，整词、空替换、只读、锁定、失效范围和任一批量风险都在落模前原子处理，一次全部替换只形成一个历史单元。
- 会话级控制器以按页懒缓存驱动 view/edit、多视图和 adapter；事务只淘汰脏页或交互状态所属页，页序变化只重组结果。快捷键、ARIA、失效重基、选区保持与跨页事件视图均通过真实 Chromium；HTML 与原生 SVG 静态文字都提供精确 Range 高亮，导航只更新前后范围而不重写整页计数 DOM。React/Vue 只消费 `snapshot.textSearch` 与同一组 adapter 动作，`canReplace` 明确区分产品 view 模式和文件只读。
- 最终 Chromium 实测 200 页首次索引 / 冷查询 p95 / 单页增量替换为 `1.7 / 0.6 / 0.6ms`，60 元素导航 / 替换完整反馈 p95 为 `0.1 / 1.8ms`；默认预览不建立索引。确定性固件 `sample-editor-find-replace.pptx` 两次 SHA-256 均为 `ecdffe947ec383f331936b4f9fb41dc144805b649e85ead54f333018bec92097`。
- 保存契约验证只改实际命中的两个 slide part，未知相邻 XML、动态/自定义字段、公式、未命中页、撤销重做、连续保存和恢复回放均保持；LibreOffice 实际打开三页产物并导出 `70897` 字节 PDF，完整 Office 清单也全绿。Windows PowerPoint 真机证据继续由任务 010 管理，不用替代证据冒充。
- 精确运行 `npm run check && npm test && npm run build` 全绿：core 2135、edit-core 831、保存 330、PowerPoint 证据契约 9、editor 331、框架适配 8、64 份固件 / 193 页 / 386 对 HTML/SVG 原始指纹等价、metafile 130，七个发布包全部构建成功；规范与需求两路最终审查均为 0 项发现。
