# 本机文件双路径保存

官网编辑器负责浏览器权限和文件交付；发布包不包含 File System Access 调用或文件句柄。

| 操作 | 行为 |
|---|---|
| 保存到文件 / Ctrl/Cmd+S | 安全上下文且支持 `showSaveFilePicker` 时先选择 `.pptx`，成功后同一文稿复用目标 |
| 另存为 / Ctrl/Cmd+Shift+S | 重新选择目标；新目标交付失败时保留原目标 |
| 保存副本 | 始终通过下载交付，不覆盖已选择的目标文件 |
| 不支持选择器 | 隐藏本机保存按钮；保存快捷键回退下载，不用 UA 判断 |
| 取消 / 权限拒绝 / 写入失败 | 保留编辑和历史，不自动改走下载；可重试或主动保存副本 |
| 旧 `.ppt` | 用户确认转换后才能保存，只接受 `.pptx` 目标，不能把 PPTX 字节写到 `.ppt` |
| 新建 / 打开 / 刷新恢复 | 不继承上一个编辑会话的句柄；普通文件输入也不授予原地覆盖权限 |

## 交付与保存点

```text
真实用户激活 → 选择/授权目标 → 捕获版本 → 序列化 → write → close → 确认该版本
                                  │             │
                           期间变化：拒绝交付   期间编辑：保留新状态
```

- 只有 `close()` 成功才记住目标并确认交付；失败时尝试 `abort()`，保留原生错误。
- 生成期间发生文稿变化，拒绝写入混合版本，提示再次保存。
- 写入期间可继续画布编辑。确认实际写入的版本，不盲目把当前版本清为已保存；撤销回旧保存点也不能例外。
- 文件任务串行执行；重复快捷键、新建和文件输入不能在写入中替换文稿。
- 文件名是用户内容，中英文切换不翻译或解释为 HTML。状态、按钮和目标提示随语言切换。
- 下载只能确认浏览器已接受交付，不能检测用户后来在下载面板取消或操作系统最终是否保存。

宿主分离交付与字节生成的公共入口：`@web-ppt/edit-core/save` 的 `serializeEditDoc(doc)` 和
`Editor.captureSavepoint()`，调用、资源释放及恢复兼容约定见[编辑核心说明](../packages/edit-core/README-zh-CN.md)。
已有 `Editor.save()` / `saveDetailed()` 保持“生成字节后确认”的便捷语义。

## 验证边界

| 证据 | 覆盖 |
|---|---|
| 真实浏览器文件句柄 | 选择器边界返回 OPFS 的真实 `FileSystemFileHandle`，实际写入、关闭、读回并通过产品输入重开 |
| 文件故障 | 选择取消、权限拒绝、create/write/close 失败、部分写入后中止、错误扩展名、不同目标失败与重试 |
| 并发输入 | 网络边界延迟实际序列化模块；慢 close 中原生移动、撤销、重做；任务锁与语言切换 |
| 产品操作 | 原生保存快捷键、Tab/Enter 另存为、320px 触点保存、真实可访问树 |
| 会话与格式 | `.ppt` 转换、新建文稿、真实下载重开、IndexedDB 冷恢复后重新选择目标 |
| 编辑核心 | 保存版本合并屏障、一次性确认、脏状态/历史往返、JSON 恢复帧重放 |

这些自动化证据不冒充操作系统原生选择对话框或 Windows PowerPoint 真机验收。
恢复记录依然绑定最初输入字节的 fingerprint：不持久化文件写入权限，也不会自动匹配原地覆盖后的新字节。

专项：`SITE_I18N_ONLY=file-save npm run test:site:i18n`。完整交付还须运行全仓四项门禁及不带专项过滤的
`SITE_BASE=/`、`SITE_BASE=/web-ppt/` 两次生产回归。

规范：[用户激活与文件交付](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、
[权限与选择器](https://wicg.github.io/file-system-access/)。
