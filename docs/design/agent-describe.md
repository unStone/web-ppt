# Agent 结构化读出

001 票据定义了范围与验收。本方案实现纯同步、只读的 `describePresentation(doc, options?)`，供外部 Agent 读取已有编辑会话；没有模型调用、网络请求或 DOM。

| 决策 | 契约与原因 |
|---|---|
| 入口 | `@web-ppt/edit-core/describe` 独立构建，复用已有编辑查询，基础入口不引用新模块 |
| 身份 | 保留 `EditDoc` 页、元素和设计画布身份；跨进程重复解析须显式使用相同 `createDoc` 的 `idPrefix`，不改变现有会话随机隔离规则 |
| 内容 | 页序、隐藏、版式/母版、节、备注；元素按绘制序先序展开，带祖先路径、有效文字、替代文字、编辑能力与页面坐标包围盒 |
| 继承 | 占位符按已有 idx 优先/等价类型规则匹配版式与母版，返回来源元素身份；当前设计投影中的静态对象映射回真实设计记录 |
| 文字 | 段落级纯文字、层级及项目符号；表格保留单元格坐标，组不重复聚合子元素文字；不输出图片 URL、原始 XML 与 run 样式 |
| 框架对象 | 图表/SmartArt 等只返回宿主编辑身份并聚合当前内部文字，沿用既有 DOM 绑定跳过框架内部投影节点的约定；数据编辑后重新生成的绘制节点不能冒充稳定命令目标 |
| 预算 | `maxChars` 约束完整紧凑 JSON 的 UTF-16 长度；`maxTokens` 要求调用方提供确定的 `countTokens`。只保留页面/元素的完整先序前缀，不切断文字和 JSON；省略数量与首个省略位置计入预算 |
| 失败 | 非法预算、缺少分词计数器、连最小结果也装不下、无效元素身份/几何均抛带稳定 reason 和定位的错误；不给出假成功 |
| Schema | 使用 `ts-json-schema-generator` 从公开 TypeScript 输出类型生成 Draft-07 Schema，Ajv 校验所有固件；两项均为开发依赖，发布包无新依赖 |

| 实施顺序 | 首个可验证节点 |
|---|---|
| 输出类型与按需入口、Schema 生成和专用确定性固件 | 新契约测试先失败；生成器可在 check 模式发现 Schema 漂移 |
| 当前投影读取、占位符来源与坐标复用 | 检查组合缩放/旋转、占位符继承、文字/表格、编辑后查询、每个返回 ID 可被 Editor 选中 |
| 预算裁剪与失败协议 | 完整输出、刚好装下、超预算、多页边界、中文/转义字符和不合法计数结果 |
| 产物与全量回归 | 全部 pptx/ppt 固件 Schema 校验；每份固件两独立进程逐字节比对；冷加载与入口闭包审计；check → test → build → verify |

只读接口不产生历史、恢复帧、协同补丁或保存改动；测试核对查询前后的文档不变，文件往返由既有保存门禁承担。Windows 真机沿用暂缓约定。
