# API 冻结候选与漂移检查

本轮对应 roadmap 的 1.0 API 准备，交付到 `0.8.0-beta.4`。候选清单不表示 1.0 已冻结，真实 ChartEx 语料、beta 反馈与 Windows 真机条件继续按 roadmap 执行。

| 顺序 | 实施 | 验证 |
|---|---|---|
| 1 | 从九包公开 exports、四份 JSON Schema、恢复与协同协议生成候选清单，保留条件导出、类型与 CLI 资源 | 对新增/移除入口、Schema 变化、协议版本变化及缺失产物做变异测试 |
| 2 | 增加 describe、lint、fill、MCP 与持久化协议的公开类型正反例 | 源码检查与发布声明检查，负例失效时编译失败 |
| 3 | 在统一测试与 verify 中检查候选清单；更新迁移与实验性能力边界 | 干净环境四项门禁、固件确定性、CI |
| 4 | 九包同步 beta 版本，按 OIDC 发布到 next | 官方 registry 逐包版本、隔离安装与真实 MCP 握手 |

检查器只进入仓库工具，不增加 SDK 运行依赖。清单更新必须显式执行并审查差异；日常检查只读取候选清单，不能用自动重写隐藏接口变化。

四份 Schema 比对规范化 JSON 的摘要，忽略键顺序和排版；协议值使用 TypeScript 编译器读取公开声明，避免通过文本搜索误认私有或失效定义。产物检查要求目标文件存在，不能以未构建为理由跳过。
